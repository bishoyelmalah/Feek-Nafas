System Concept & Project Vision

The Asynchronous Problem

Traditional coding contests lack the adrenaline of direct, live combat. Isolation leads to lower engagement.

  • Lengthy durations (2-3 hours).
  • Competing against ratings, not people.
  • No immediate peer interaction.

The Synchronous Solution

A real-time 1v1 battle arena where speed and stamina are as vital as algorithm knowledge.

  • Head-to-Head: First solve wins instantly.
  • Live Sync: Real-time opponent tracking.

Core Functional Pillars

  • Dynamic Matchmaking: Problems assigned via ELO rating boundaries (800-3000) and specific topic tags.
  • Serverless Referee: Background validation via Supabase Edge Functions polling the Codeforces API.
  • Competitive Gamification: Mathematical skill tracking via a robust ELO ranking system.

1. The Entry Point: Landing Page

Public Routing & Immersion

The LandingPage.tsx serves as the unauthenticated entry point to the application.

  • Wrapped in a <PublicRoute> to ensure logged-in users are automatically redirected to the dashboard.
  • Establishes the core visual identity (Cyberpunk/Neon aesthetics).
  • Clear Call-To-Action (CTA) routing users to the authentication flow.

2. Onboarding: Sign Up

Data Seeding & Registration

Handled by the RegisterPage.tsx component.

  • Account Creation: Registers the user's email and password securely with Supabase Auth.
  • Database Initialization: Triggers a database insertion to the users table to create a custom profile.
  • Base Stats: Automatically assigns the user a starting ELO rating (e.g., 800) and an initial avatar.

3. Security: Email Verification

Account Activation

After registration, the system enforces email verification before granting full platform access.

  • Supabase Integration: Automatically dispatches a secure OTP/Verification link to the registered email address.
  • Access Control: The <ProtectedRoute> wrapper intercepts and blocks unverified users from accessing the dashboard.
  • Activation: Clicking the link validates the JWT and activates the user profile in the Postgres database.

4. Authentication: Sign In

Session Management

Handled by the loginPage.tsx component.

  • Service Layer: Validates user credentials via authService.ts communicating directly with Supabase Auth.
  • Global Context: On successful login, the JWT token is securely stored. The AuthContext.tsx detects the active session and re-renders the app state.
  • Routing: User is seamlessly redirected to the protected dashboard.

5. The Dashboard: Home Page

Player Hub & Analytics

The HomePage.tsx acts as the central command center for authenticated users.

  • Protection: Secured behind the <ProtectedRoute> wrapper.
  • Data Fetching: Uses userService.ts to pull the player's current ELO, rank badge, and match history.
  • Action: Serves as the primary launchpad to enter the matchmaking queue.

6. Parameterization: Find Match

Dynamic Problem Allocation

In FindMatchPage.tsx, users configure the battle constraints:

  • Filters: Select Rating (800 - 3000), Topic (DP, Math, etc.), and Duration (15 - 60 mins).
  • API Integration: codeforcesService.ts queries the CF problemset, applies the filters, and selects a random valid problem.
  • Database Creation: createMatchService.ts inserts a new record into the matches table and generates the matchId.

7. Synchronization: Get Ready Phase

Supabase Postgres Changes Sync

The GetReadyPage.tsx relies on real-time database row tracking to prevent late-joiner issues.

  • Channel Init: Subscribes to postgres_changes for the specific matchId.
  • Payloads: Players toggle player1_ready or player2_ready in the database. UI updates instantly on trigger.
  • State Lock-In: When both states evaluate to true, a strict 3-second interval locks the UI. At 0, useNavigate routes players to the arena.

8. The Live Arena: Match Page

The Serverless Referee System

The MatchPage.tsx mounts, rendering the CF problem and initiating the useMatchTimer.

  • Anti-Cheat: We do not trust client-side claims of victory.
  • Polling: Background services continuously poll the Codeforces user.status endpoint.
  • Detection: Upon detecting an OK verdict matching the contestId and index, the match instantly halts.

9. Resolution: Victory

The Winner's Flow

When the Referee system validates a user's submission first:

  • Routing: The winning client is pushed dynamically to VictoryPage.tsx.
  • Audio Cues: victory_sound.mp3 plays automatically on component mount.
  • State Update: A positive ELO calculation is applied and pushed to the Supabase backend, updating the player's overall rank.

10. Resolution: Defeat

The Loser's Flow

When the opponent's submission is validated first, or the time expires:

  • Routing: The losing client is instantly pushed to LosePage.tsx.
  • Audio Cues: lose_sound.mp3 is triggered to signal the end of the match.
  • State Update: A negative ELO deduction is calculated and synchronized, reflecting a drop in the player's competitive rank.
